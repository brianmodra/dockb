# API Design: Frontend ↔ Backend

## Core Principle

**Semantic events, not text diffs.** The FE tells the BE *what* changed in the hierarchy, not *where* in a flat character buffer. Mapping between character positions and model elements is maintained by ProseMirror's tree resolution on both sides — no fragile position-mapping code in either frontend or backend.

Tokens are **server-only** — computed by `SentenceTokenizer`/spaCy, stored in Neo4j, and never transmitted over the wire.

---

## Wire Format (ProseMirror JSON)

The native ProseMirror document format. Parseable by `prosemirror-py` on both ends without transformation.

```json
{
  "type": "doc",
  "attrs": { "id": "doc-uuid" },
  "content": [
    {
      "type": "chapter",
      "attrs": { "id": "ch-uuid", "title": "Introduction" },
      "content": [
        {
          "type": "paragraph",
          "attrs": { "id": "p-uuid" },
          "content": [
            {
              "type": "sentence",
              "attrs": { "id": "s-uuid" },
              "content": [
                { "type": "text", "text": "Hello world." }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

### Schema

```
doc:       { content: "chapter+" }
chapter:   { content: "paragraph+", attrs: { id: string, title: string } }
paragraph: { content: "sentence+",  attrs: { id: string } }
sentence:  { content: "text*",      attrs: { id: string } }
text:      { inline: true }
```

### ID Convention

All node IDs are UUIDs (v4) generated by the creator. Since UUIDs are globally unique, the FE can generate IDs for new nodes without conflict. No temporary-ID mapping is needed.

## REST Endpoints

### Document CRUD

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/documents` | List document summaries |
| `POST` | `/api/documents` | Create empty document, returns `{id}` |
| `GET` | `/api/documents/{id}` | Full tree as ProseMirror JSON |
| `PUT` | `/api/documents/{id}` | Full replacement (prototype round-trip) |
| `DELETE` | `/api/documents/{id}` | Delete doc + all children |

### Event API (production)

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/documents/{id}/events` | Send batched edit events, receive structural changes |
| `GET` | `/api/documents/{id}/events?since=N` | Poll for pending BE→FE events |

### WebSocket (future)

```
WS /api/documents/{id}/ws
```

Bidirectional real-time communication. Same event types as REST.

## Event Types

### FE → BE

| Event | Payload | When |
|---|---|---|
| `edit_sentence` | `{ sentence_id, text }` | User types in a sentence |
| `insert_sentence` | `{ paragraph_id, after_sentence_id, text }` | User adds a new sentence |
| `delete_sentence` | `{ sentence_id }` | User deletes a sentence |
| `insert_paragraph` | `{ chapter_id, after_paragraph_id }` | User adds paragraph between existing |
| `delete_paragraph` | `{ paragraph_id }` | User deletes paragraph |
| `insert_chapter` | `{ document_id, after_chapter_id, title }` | User adds chapter |
| `delete_chapter` | `{ chapter_id }` | User deletes chapter |

Where `after_*` can be `null` to indicate insertion at the beginning.

### BE → FE

| Event | Payload | When |
|---|---|---|
| `sentence_edited` | `{ sentence_id, text }` | Confirmation of edit |
| `sentence_split` | `{ original_id, before_id, before_text, after_id, after_text }` | BE detected a sentence boundary in edited text |
| `sentence_inserted` | `{ sentence_id, after_id, text }` | New sentence created (split or FE-initiated insert) |
| `sentence_deleted` | `{ sentence_id }` | Sentence removed |
| `paragraph_inserted` | `{ paragraph_id, after_id }` | New paragraph created |
| `paragraph_deleted` | `{ paragraph_id }` | Paragraph removed |
| `chapter_inserted` | `{ chapter_id, after_id, title }` | New chapter created |
| `chapter_deleted` | `{ chapter_id }` | Chapter removed |
| `error` | `{ code, message }` | Processing failure |

## Example Flows

### User types in a sentence (no split)

```
FE ── POST /api/documents/d-1/events ──► BE
     [{ "type": "edit_sentence",
        "sentence_id": "s-1",
        "text": "Hello world." }]

BE ◄── { "ok": true, "seq": 42, "changes": [] } ── FE
```

### User types a period — BE detects a split

```
FE ──► BE
     [{ "type": "edit_sentence",
        "sentence_id": "s-1",
        "text": "Hello. New sentence here." }]

BE ◄── {
  "ok": true,
  "seq": 43,
  "changes": [
    { "type": "sentence_split",
      "original_id": "s-1",
      "before_id": "s-1",
      "before_text": "Hello.",
      "after_id": "s-2",
      "after_text": "New sentence here." }
  ]
} ── FE
```

The FE updates its ProseMirror document: sentence s-1 text becomes `"Hello."`, new sentence s-2 appears after it.

### Batch typing (FE coalesces rapid keystrokes)

```
FE ──► BE
     [
       { "type": "edit_sentence", "sentence_id": "s-1", "text": "H" },
       { "type": "edit_sentence", "sentence_id": "s-1", "text": "He" },
       { "type": "edit_sentence", "sentence_id": "s-1", "text": "Hel" },
     ]

BE ◄── { "ok": true, "seq": 44, "applied": [
  { "type": "edit_sentence", "sentence_id": "s-1", "text": "Hel" }
]} ── FE
```

The BE deduplicates by `sentence_id` — only the last value per ID is applied; earlier values are acknowledged but skipped.

### Insert a sentence between existing ones

```
FE ──► BE
     [{ "type": "insert_sentence",
        "paragraph_id": "p-1",
        "after_sentence_id": "s-2",
        "text": "This goes between s2 and s3." }]

BE ◄── {
  "ok": true,
  "seq": 45,
  "changes": [
    { "type": "sentence_inserted",
      "sentence_id": "s-4",
      "after_id": "s-2",
      "text": "This goes between s2 and s3." }
  ]
} ── FE
```

### BE processing chain

For each edit event, the backend:

1. Looks up the affected model(s) by ID
2. Applies the change synchronously (text update, child insert/delete)
3. Marks affected models as dirty
4. Enqueues `DeleteJob` + `ReconstructJob` for async semantic reprocessing
5. Returns immediately with a seq number and any structural changes detected during synchronous processing

Reconstruction runs asynchronously:
1. `DeleteJob` clears old tokens/semantics
2. `ReconstructJob` re-runs hydrators/tokenizers (spaCy)
3. `CommitJob` persists via `UnitOfWork` → Neo4j
4. If structural changes are detected (sentence split), a callback pushes `sentence_split` events

## Prototype Shortcut (Phase 1)

The event API is not needed for Phase 1 validation. The prototype uses a simpler round-trip:

```
PUT /api/documents/{id}   ← FE sends full ProseMirror JSON
GET /api/documents/{id}   ← BE returns processed version
```

Steps:
1. FE creates document → `POST /api/documents`
2. FE edits locally in prosemirror-py + Textual TUI
3. FE does `PUT /api/documents/{id}` with the modified full document
4. BE deserializes ProseMirror JSON → hydrates → tokenizes → persists to Neo4j
5. FE does `GET /api/documents/{id}` — gets back identical structure, verifies round-trip

This validates the full pipeline (serialization, deserialization, hydration, tokenization, persistence) without implementing the event system first.

## Error Responses

```json
{
  "error": {
    "code": "sentence_not_found",
    "message": "No sentence with id 's-999' exists in document 'd-1'."
  }
}
```

| Code | HTTP Status | Meaning |
|---|---|---|
| `document_not_found` | 404 | Document ID does not exist |
| `sentence_not_found` | 404 | Sentence ID does not exist in this document |
| `paragraph_not_found` | 404 | Paragraph ID does not exist in this document |
| `chapter_not_found` | 404 | Chapter ID does not exist in this document |
| `invalid_payload` | 422 | JSON body does not match expected schema |
| `processing_error` | 500 | spaCy/hydration/internal failure |
| `conflict` | 409 | Document version mismatch (optimistic locking) |

## Future Considerations

- **Authentication/OAuth**: Session context (SessionContext) holds JobQueue + DocCache per user
- **Real-time push**: WebSocket replaces polling for BE→FE events
- **Optimistic locking**: Document version number in `attrs.version` for conflict detection
- **Collaborative editing**: pycrdt/Yjs integration with the same event schema
